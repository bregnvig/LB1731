Filter vs. truthy / Falsy as a guard

type nullish = null | undefined;
export const truthy = <T>() => 
	pipe(filter(x => !!x) as OperatorFunction<T | nullish | '', T>);
export const falsy = <T>() => 
	pipe(filter(x => !x) as OperatorFunction<T | nullish, T extends number 
		? (nullish | 0) 
		: T extends string ? (nullish | '') : nullish>);

this.service.getPlayground(id).pipe(
  truthy()
).subscribe(playground => this.name = playground.name);

a TypeScript thing

Working with nullable or undefined values... truthy() and falsy() can also be used as type guards, filtering out null, undefined, or other falsy values safely. By leveraging TypeScript we're enhancing type safety. Like this we can safely access properties without needing null checks all the time! (Highlight that the elvis operator (?) is not needed anymore)
