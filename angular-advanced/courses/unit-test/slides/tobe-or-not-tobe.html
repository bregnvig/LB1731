Tobe or not tobe

Expect

expect(x).toBe(...):

  • deep equality
  • same structure (even if different ref)

expect(x).toEqual(...):

  • Object.is(x, y)
  • identity (exactly same value)

(If in doubt just use toEqual)

Explain about toBe vs toEqual Intent is obvious, and Obvious is always better. It is reasonable to expect other developers to be familiar with how === works and to understand we are purposefully checking if both variables reference the same value. Consistency. Using .toEqual for this will match the rest of your tests. It should be the default choice when doing matchers. Reduces reliance on assumptions. (Assuming everyone knows how .toBe works. Which they don't. I literally had to correct the stack overflow post after looking up the Jest source code). Reduces need for communication. (Verifying that everyone knows how .toBe, and by extension, Object.is works.)
