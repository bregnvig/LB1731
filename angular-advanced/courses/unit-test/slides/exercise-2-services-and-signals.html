Testing a service that holds a signal

import { Service } from '@angular/core';

@Service()
export class FavoritesService {
}
beforeEach(() => {
  service = TestBed.inject(FavoritesService);
});

// Act
// Assert
expect(service.favoriteIds()).toEqual([...]);

@Service() is what npx ng g s generates in Angular 22.

TestBed.inject(FavoritesService) gives the test a real instance. No constructor, no manual new.

A signal is a function: you read it by calling it, favoriteIds().

Test the public API, not private fields. Call toggle, read favoriteIds(). If you rename a private field the tests should still pass.

@Service() + TestBed.inject. Read a signal by calling it. Public API only: toggle in, favoriteIds() out. The service is a plain class with @Service(), which is what ng g s generates in Angular 22. It uses inject() instead of constructor parameters. In a test you do not call new. TestBed.inject(FavoritesService) builds it the way Angular would. A signal is read by calling it, so the assertion is expect(service.favoriteIds()).toEqual([...]). Test through what the service exposes. If the test reaches into a private field, every refactoring of the internals breaks it for no reason. Tests should only go red when behaviour changes. The tests are zoneless via src/test-providers.ts, which matters in later exercises more than here.
