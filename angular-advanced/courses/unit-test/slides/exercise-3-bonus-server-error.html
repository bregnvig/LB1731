Which behaviour did you just pin down? Who decides what the user sees on an error?

// Arrange
const result = firstValueFrom(service.search('christianshavn'));
// Act
httpTesting.expectOne('assets/copenhagen.json').flush('Server error', { status: 500, statusText: 'Internal Server Error' });
// Assert
await expect(result).rejects.toMatchObject({ status: 500 });
Bonus. Third case in playground.service.spec.ts: 'should reject when the server fails'. Answer to the last question: the service lets the error through; the caller decides. If you are done early, test the unhappy path. flush can answer with an error: pass a status of 500. The observable errors, so firstValueFrom rejects.
