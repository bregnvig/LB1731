Never trust a test you did not see fail

A test that has never been red may check nothing.

It passes before your code exists, or it compares a value with itself.

So the red step is the proof that the test can fail.

expect(filterPlaygrounds(list, 'x')).toEqual(filterPlaygrounds(list, 'x'));

Always green. Always useless.

“Never trust a test that you didn’t see fail”

Jennifer Wadella
VP of Frontend Engineering, Bitovi
CypressConf 2023 keynote on testing

Quote: "Never trust a test that you didn't see fail", Jennifer Wadella (VP of Frontend Engineering at Bitovi, an Angular consultancy; CypressConf 2023 keynote on testing). A test never seen red may test nothing. Jennifer Wadella says: never trust a test you did not see fail. A passing test only tells you something if it could have failed. A test can pass for the wrong reasons: the code was already there, the assertion compares a value with itself, or you forgot the expect. So in TDD, red is not a formality. You run the new test before the code exists and read the failure. If it is green on the first run, the test is wrong.
