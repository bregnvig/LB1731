Test Doubles

MOCKS

Gives full control over module/object

import { DateTime } from 'luxon';
import { vi } from 'vitest';
...

vi.mock('luxon', async () => ({
    ...(await vi.importActual('luxon')),
    DateTime: { now: () => true },
}));

describe('Luxon service', () => {
  it('should return true', () => {
    expect(DateTime.now()).toBe(true);
  });
});
Mocks are rarely used A Mock is the most powerful and flexible version in the chain of test doubles. The behavior of the mocked interface can be changed dynamically based on scenarios. Mocks are pre-programmed with expectations which form a specification of the calls they are expected to receive. They can throw an exception if they receive a call they don't expect and are checked during verification to ensure they got all the calls they were expecting.
