Resource Api - Why it matters

Resources give you one consistent way to do it all 🥳

The Resource API brings a unified pattern for:

  • Fetching data
  • Caching it efficiently
  • Reacting to updates automatically


Think: fetch → cache → react

Today each team loads data its own way: subscribe in ngOnInit, a loading flag, an error flag, maybe a switchMap. Resources are one pattern for all of it. You describe what to load from which signals, and you get the value, the loading state and the error as signals. When the signals change, it loads again and cancels the old request. Think: fetch, cache, react.
