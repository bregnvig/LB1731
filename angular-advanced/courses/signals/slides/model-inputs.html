Model inputs

Stable since v19

Data binding and change event

Writable input signal using set / update

No support for transformers

Clients can use either signals or primitives

<loop-pagination 
  [items]="playgrounds" 
  [template]="playground" 
  [(page)]="page" />

Use two way data binding

export class PaginationComponent {

  template = input.required<TemplateRef<any>>();
  items = input.required<unknown[]>();

  page = model<number>(0);
  // And more....
}

Define two way data binding

<loop-pagination 
  [items]="playgrounds" 
  [template]="playground" 
  [(page)]="page" />

Use one way data binding

<loop-pagination 
  [items]="playgrounds" 
  [template]="playground" 
  [page]="page()" />

<loop-pagination 
  [items]="playgrounds" 
  [template]="playground" 
  [(page)]="page" />

Use implicit change event

<loop-pagination 
  [items]="playgrounds" 
  [template]="playground" 
  (pageChange)="pageChanged($event)" />
Two-way [(page)] takes the signal itself; one-way [page] takes its value, page(). Demo: /signals/model (demo/src/app/signals/model). Its page is a linkedSignal: the pagination writes it, and switching city resets it to the first page.
