Types and order

type Response = Observable<boolean | UrlTree> | Promise<boolean | UrlTree> | boolean | UrlTree;

interface CanDeactivate<T> {
    canDeactivate(component: T, currentRoute: ActivatedRouteSnapshot,
        currentState: RouterStateSnapshot, nextState?: RouterStateSnapshot
    ): Response;
}

interface CanLoad {
    canLoad(route: Route, segments: UrlSegment[]): Response;
}

interface CanActivateChild {
    canActivateChild(childRoute: ActivatedRouteSnapshot, state: RouterStateSnapshot): Response;
}

interface CanActivate {
    canActivate(route: ActivatedRouteSnapshot, state: RouterStateSnapshot): Response;
}

These are all deprecated

A guard implements one of the showed interfaces Can Load/Activate/ActivateChild -> Restrict access to a specific route (Might be some prerequisites need to be met). CanDeactivate -> Restrict from navigating away from a route (Maybe the user has unsaved changes or needs to confirm terms before using the app) All types of guards either returns a response that "flattens" to a boolean or a UrlSegment[]/UrlTree Guards are processed in the order shown in the code example We're not talking about CanActivateChild canLoad -> We'll talk about this later
