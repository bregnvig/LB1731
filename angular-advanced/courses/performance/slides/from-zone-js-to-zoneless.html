From Zone.js to zoneless

  • Zone.js patches browser events, timers and promises, and checks components after every one
  • It only knows something might have changed 🤔
  • Since v21, new apps are zoneless: signals tell Angular exactly which views to update
  • This app still opts in to Zone.js. Today we opt out
// src/main.ts in this app
providers: [
  provideZoneChangeDetection(),
  ...
]

// A new app since v21: nothing.
// Zoneless is the default.

// Today:
provideZonelessChangeDetection(),
Zoneless: Angular is told about changes (signal, event, markForCheck), it does not guess. Opting out = remove zone.js from polyfills + provideZonelessChangeDetection(). runOutsideAngular stays: the docs say it remains compatible. Zone.js guesses; zoneless is told. Without Zone.js nothing patches the browser. Angular learns about changes directly: a signal that a template reads, an event listener in a template, the async pipe, markForCheck. New apps since v21 are zoneless and write nothing in main.ts. Our app still has provideZoneChangeDetection. In exercise 2 you replace it with provideZonelessChangeDetection and remove zone.js from the build. Your runOutsideAngular from exercise 1 can stay: the Angular docs say it is still compatible with zoneless, because libraries may still run in zone apps. It just does nothing functionally.
