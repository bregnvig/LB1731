Running outside Zone.js

export class ChangeDetectionComponent implements AfterViewInit {

  div = viewChild.required<ElementRef<HTMLElement>>('outside');
  #zone = inject(NgZone);

  ngAfterViewInit(): void {
    this.#zone.runOutsideAngular(() =>
      this.div().nativeElement.addEventListener('mousemove', event => this.mouseMove(event)));
  }

  mouseMove(event: MouseEvent) {
    console.log('Mouse move', event);
  }
}
  • Code started inside runOutsideAngular never triggers Zone.js: no change detection after it
  • Good for high-frequency events and third-party libraries. But nothing tells Angular about changes either: update state with a signal, or call NgZone.run
Only the listener registration goes outside. Same log output, different profiler. Careful: you are switching Angular off for that code. Original slide mixed #zone and this.zone: fixed here. Here is the tool. NgZone.runOutsideAngular takes a function and runs it outside the zone. Anything it starts, like this event listener, is not patched by zone.js, so when the mouse moves, Angular does not run change detection. Show the green example: the log looks the same, but in the profiler there are no bars. It is a power tool. You are cutting the wire between this code and Angular. Use it for high-frequency events and third-party libraries that manage their own DOM, and be sure that nothing in your templates depends on what happens in there. If it does, update a signal, or hop back in with zone.run.
