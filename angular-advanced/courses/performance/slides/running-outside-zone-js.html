Running outside Zone.js

Code started in runOutsideAngular() triggers no change detection

For third-party code that fires often, like a map

The catch: Angular isn't told about changes in there. Set a signal

export class LeafletComponent implements AfterViewInit, OnDestroy {

  private zone = inject(NgZone);

  ngAfterViewInit() {
    const _map = this.zone.runOutsideAngular(() => mapContructor(this.mapId, {
      zoomControl: false,
      center: undefined,
      zoom: 7,
      minZoom: 4,
      maxZoom: 19,
      layers: [...]
    }));
    control.zoom({ position: 'topleft' }).addTo(_map);
Demo: /performance/change-detection. All Eager, click setTimeout on B: every node flashes, checks 2 each (zone entry + timer). Reset, click "outside zone" on B: nothing flashes, B's field stays stale. The function returns the map, so const _map stays. Here's the tool. NgZone.runOutsideAngular takes a function and runs it outside the zone. Anything it starts, event listeners and timers, isn't patched, so Angular doesn't run change detection after them. Switch to the demo. All Eager, Reset counters, click setTimeout on B. Every node flashes, and the counters say two checks each: one for the click, one for the timer. Reset, click outside zone on B. Nothing flashes. B's field did change, but the screen still shows the old value. Ask the room: when will B show the new number? At the next cycle, whatever starts it. That's the catch. You're cutting the wire between this code and Angular. Fine for a map that draws its own DOM. If a template depends on it, set a signal. The code is exercise 1. Click: the map is created inside runOutsideAngular, and the arrow function returns it, so const _map still works. Leaflet adds its listeners when the map is created, so wrapping creation is enough.
