Preloading and canMatch

  • Lazy: the first visit waits for the chunk
  • withPreloading fetches chunks in the background
  • canMatch false: the chunk is never downloaded
provideRouter(AppRoutes,
  withPreloading(PreloadAllModules)),
// a lazy route behind a guard
{
  path: 'admin',
  canMatch: [() => inject(Auth).isAdmin()],
  // …
},
Only if asked. PreloadAllModules: fetch every lazy route after the first render. canMatch, not canLoad: runs before the chunk is fetched. The price of a lazy route is a wait the first time the user goes there. Preloading removes that wait without making the start slower: after the app is up, the router fetches the lazy chunks in the background. If that's too greedy, write your own PreloadingStrategy. Guards: use canMatch. It runs when the router matches the route, so if it returns false the chunk is not downloaded.
