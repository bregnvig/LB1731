Reading the build output

npm run build: the chunk table

Initial: before the app starts

Lazy: fetched later

Raw: the file. Transfer: compressed

The line to watch: Initial total

Four clicks, then the line to watch. Initial = downloaded before anything shows. Lazy = fetched later (no lazy table yet). Raw is the file, transfer is the estimate after compression. Look at both. Optional: ng build --stats-json writes stats.json for a bundle analyzer. Before we change anything, we learn to read what the build tells us. npm run build, and look at the table it prints. On the slide are the two lines we care about. The first table is the initial chunk files: everything the browser has to download and run before the app starts. The Initial total line is the number we want to push down. Raw size is the file on disk. Estimated transfer size is what goes over the wire after compression. Users on a slow connection feel the second one; parsing and running cost the first one. Once something is lazy, a second table shows up: lazy chunk files. You'll see it appear in the exercise. The hashes in the file names change between builds. That's fine, it's how the browser cache knows a file is new.
