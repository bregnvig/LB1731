Initial = downloaded before anything shows. Lazy = fetched later. Raw is the file, transfer is the estimate after compression. Look at both. Numbers are step-3 of this course (zoneless, nothing lazy yet). Exercise 3 starts here: students run the build and write down Initial total. Before we change anything, we learn to read what the build tells us. Run ng build and look at the table. The first table is the initial chunk files: everything the browser must download and run before the app starts. The Initial total line is the number we want to push down. Raw size is the file on disk. Estimated transfer size is what goes over the wire after compression. Users on a slow connection feel the second one, parsing and running feel the first one. Once we add lazy loading a second table appears: lazy chunk files. Those are loaded later, when something asks for them. In our app, main is 1.53 MB. That is the number to attack. If you want a picture, ng build --stats-json writes a stats.json file that a bundle analyzer can open. Note the hashes in the file names change between builds, that is fine.
