Good: no markForCheck, no cleanup (injection context destroy), computed lazy + memoised. Three clicks, then the punchline. Cut from the slide: toSignal unsubscribes and effect is destroyed with the component; computed only runs when read. Moving to signals is mostly good news. A signal read in a template tells Angular to update that view, so no markForCheck. toSignal unsubscribes when its injection context is destroyed, and an effect is destroyed with it, so there is no cleanup code. And computed is lazy and memoised: if nobody reads it, the function never runs, and if the inputs did not change, it does not run again.
