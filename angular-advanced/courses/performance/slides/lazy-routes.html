Lazy routes

loadComponent for one standalone component

loadChildren for a route tree

Remove the static import at the top, or the code stays in main

The step-4 detail route is in the exercise

{
  path: 'legeplads/:id',
  loadComponent: () =>
    import('src/app/playground-detail/playground-detail.component')
      .then(m => m.PlaygroundDetailComponent),
},
{
  path: 'admin',
  loadChildren: () =>
    import('./admin/admin.routes').then(m => m.ADMIN_ROUTES),
},
loadComponent for one component, loadChildren for a whole route tree. Both take a function returning import(). The bundler splits at the import. The detail route in the exercise gets a chunk of about 1 kB: small, but the pattern is the point. Both run in an injection context. A lazy route is a route whose code is not in the first download. You give the router a function that calls import(), and the build tool puts the imported file in its own chunk. loadComponent is for a single standalone component. This is what you do in the exercise for the detail route: remove the import at the top of the routes file, and use loadComponent instead. loadChildren is for a group of routes, for instance everything under /admin. The imported file exports a Routes array, and if it is the default export you do not even need the then. Important: it only works if nothing else imports that component statically. One normal import at the top of the file and the chunk is back in main. The functions run in an injection context, so you can call inject() inside them if you need to.
