Lazy routes

loadComponent for one standalone component

loadChildren for a route tree

The bundler splits at the import()

The catch: delete the static import at the top. If any file still uses the class, it stays in main

{
  path: 'legeplads/:id',
  loadComponent: () =>
    import('src/app/playground-detail/playground-detail.component')
      .then(m => m.PlaygroundDetailComponent),
},
{
  path: 'admin',
  loadChildren: () =>
    import('./admin/admin.routes').then(m => m.ADMIN_ROUTES),
},
loadComponent for one component, loadChildren for a whole route tree. Both take a function returning import(). The bundler splits at the import. The detail route in the exercise gets a chunk of about 1 kB: small, but the pattern is the point. Trap on the slide: the static import at the top must go. A lazy route is a route whose code isn't in the first download. You give the router a function that calls import(), and the build puts that file in its own chunk. loadComponent is for one standalone component. That's what you do in the exercise for the detail route, legeplads/:id. loadChildren is for a group of routes, say everything under /admin. The imported file exports a Routes array, and if it's the default export you don't even need the then. The catch: it only works if nothing imports the component the normal way. Leave a real use of the class in another file and the chunk is right back in main. The build won't warn you, so you check the lazy table. Ask the room: which routes in your app does almost nobody visit? Those are your first loadComponent candidates. The functions run in an injection context, so you can call inject() inside them if you need to.
