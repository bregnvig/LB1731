OnPush is the default (v22)

Every component is OnPush unless it opts out

The old default is now called Eager. Every component in this app has it: it is what ng update adds to an existing app

An OnPush component is checked when

  • an input changes
  • an event fires in its template
  • a signal its template reads changes
@Component({
  selector: 'loop-footer',
  // Opts out of OnPush (the old default)
  changeDetection: ChangeDetectionStrategy.Eager,
  template: `...`,
})
export class FooterComponent {}
d.ts in node_modules/@angular/core: OnPush = 0 ("NOTE: OnPush is enabled by default."), Eager = 1, Default = 1 deprecated alias ("due to be removed"). Eager: checked whenever the traversal reaches it. Works under zone.js, it is what the footer needs while a plain field changes. Our starting app looks like that. Since Angular 22 every component is OnPush unless it says otherwise. You can see it in the type declarations in node_modules: OnPush is the first member, and its comment says OnPush is enabled by default. The old default is now called Eager, and Default still compiles as a deprecated alias that is going to be removed. Eager means check me every time the change detection traversal reaches me. That is what lets the footer's plain field work under Zone.js: the zone runs a cycle every second, and the footer is checked and picks up the new number. That is why the footer says Eager, and, like an app after ng update, so does every other component: the migration adds it everywhere so nothing changes behaviour.
