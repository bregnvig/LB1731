@placeholder, @loading and @error

  • @placeholder: before the trigger fires. minimum stops flashing
  • @loading: while downloading. after delays it, minimum keeps it up
  • @error: the download failed
@defer (on viewport) {
  <loop-footer [playground]="playground()" [loadedAt]="loadedAt()"/>
} @placeholder (minimum 500ms) {
  <footer>&nbsp;</footer>
} @loading (after 100ms; minimum 1s) {
  <footer>Henter ...</footer>
} @error {
  <footer>Kunne ikke hente</footer>
}

Reserve the space. Click: reserve the space. The block has up to three companions. The placeholder is what the user sees before the content is requested. The loading block shows while the chunk downloads. The error block shows if the download fails. Let me show you the loading block. Throttle to Slow 4G, reload, click "Click me" on the interaction card. "Loading ..." for about a second, then the real card. Ask the room: without throttling, would you have seen it at all? Two timers stop flicker. In placeholder, minimum is how long it stays once shown. In loading, after delays showing it, so a fast download never shows a spinner at all, and minimum keeps it up long enough to read. Reserve the space. If the placeholder isn't the size of the content, the page jumps when the content arrives. That's layout shift, and it counts against you. In the exercise the map placeholder is an empty full-size div and the footer placeholder is an empty footer. Whatever the placeholder, loading and error blocks use is loaded eagerly, so keep them cheap.
