Cleaning up with DestroyRef

  • DestroyRef.onDestroy: write the cleanup next to what it cleans up
  • RxJS: takeUntilDestroyed()
  • Components, directives and services, v16+
constructor() {
  const id = setInterval(
    () => this.seconds.set(…), 1000);
  inject(DestroyRef).onDestroy(
    () => clearInterval(id));

  this.stream$.pipe(takeUntilDestroyed())
    .subscribe(…);
DestroyRef.onDestroy: runs when the owner (component, directive, service) is destroyed. Register synchronously, in the constructor or right after creating the thing: after an await, registering on a destroyed owner throws NG0911. takeUntilDestroyed() with no argument only in an injection context; pass a DestroyRef elsewhere. DestroyRef is the one tool for cleanup. Inject it, and onDestroy takes a function that runs when the component, directive or service that owns it is destroyed. Both exist since Angular 16. The big advantage over ngOnDestroy: you write the cleanup right next to the thing it cleans up, and you don't store the id in a field just to reach it later. One rule: register synchronously, when you create the thing. If you register after an await and the component was destroyed in the meantime, Angular throws NG0911. For RxJS there's takeUntilDestroyed. In a constructor or field initializer you call it with no argument; anywhere else, ngAfterViewInit for example, pass in the DestroyRef, or it throws because there's no injection context. In the exercise you do the first half for the footer and the same for the Leaflet map: after you create it, register a callback that calls remove on the map.
