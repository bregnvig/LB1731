What stays eager

Only standalone components, directives and pipes

Also used outside the block (same file), or via @ViewChild: eager

Placeholder, loading and error dependencies: eager

Imported through a barrel file: chunk stays in main

Dev server with HMR loads every chunk up front: npm start -- --no-hmr

Only standalone components, directives and pipes. Used outside the block in the same file, or as @ViewChild: eager. Placeholder, loading and error dependencies are eager. Barrel file import keeps it in main. Home imports the file directly. HMR loads defer chunks eagerly: ng serve --no-hmr. SSR renders the placeholder. @defer only moves code that nothing else needs at start. That gives a few ways to quietly lose the win. The dependency has to be standalone. If anything outside the block uses it in the same file, or you grab it with a ViewChild, it stays eager. What the placeholder, loading and error blocks use is eager too. Barrel files: if you import from an index.ts that re-exports a lot, the bundler may keep the chunk in main. That is why Home imports LeafletComponent from its own file. And in this course I also removed the global Leaflet script from angular.json, since a global script loaded Leaflet in the first download whatever you did to the template. In development, hot module replacement loads every defer chunk up front, so you will not see them load. Start with npm start -- --no-hmr to see the real behaviour in the Network tab. With server side rendering the server renders the placeholder and the triggers do not run there.
