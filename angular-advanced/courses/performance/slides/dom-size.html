Every element costs memory and style/layout work. Lighthouse warns above about 800 nodes, errors above about 1400 (Chrome for Developers, updated 2024-06-21). Console: document.querySelectorAll('*').length Our list: 7 elements per row x 133 rows = about 930 from the list alone. @for needs a track expression: stable identity lets Angular reuse DOM instead of rebuilding. Every element in the page has a cost: memory, and work whenever styles or layout are recalculated. Big DOMs make every interaction slower. Lighthouse gives a rough rule: a warning above about 800 nodes and an error above about 1400. That is from the Chrome for Developers documentation page on DOM size, last updated in June 2024, so treat the exact numbers as a rule of thumb, newer Lighthouse versions fold it into an insight called Optimize DOM size. To check in your own app, run document.querySelectorAll star in the console. Ours says about 1,020, and 931 of them are the list: each row is a list item, button, div, h6, small, div and span, seven elements, times 133 playgrounds. In the template, @for requires a track expression. Tracking by id means that when the array changes, Angular keeps the rows that are still there, instead of destroying and recreating them.
