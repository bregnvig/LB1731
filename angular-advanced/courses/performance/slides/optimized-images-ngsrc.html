Images: ngSrc

  • ngSrc instead of src (NgOptimizedImage)
  • priority on the LCP image (Largest Contentful Paint). Without it, dev mode logs NG02955
  • width + height, or fill
<img ngSrc="/assets/performance/hero.webp"
     width="2400" height="1200" priority>

<div class="fill-box">
  <img ngSrc="/assets/performance/sandbox.webp" fill>
</div>
Demo: /performance/images. Console open, click Reload without priority: error NG02955 for hero.webp. Click Reload with priority: console clean. 30 seconds. The playground app has no big images, so there's no exercise. Know it for when you do. Replace src with ngSrc and import NgOptimizedImage. You get lazy loading by default, a srcset when you configure an image loader, and dev mode warnings for the usual mistakes. It matters most for LCP, Largest Contentful Paint: the time until the biggest thing above the fold has rendered. Often that's a hero image. Put priority on that one: it gets fetch priority high, isn't lazy, and with server-side rendering it's preloaded. Let me show you. Console open, Reload without priority: NG02955, Angular telling us the LCP image has no priority. Reload with priority: clean. Width and height are required, so the browser reserves the space and the page doesn't jump. If you don't know the size, use fill with a positioned parent, like the second image here. Ask the room: which image on your own start page is the LCP element? Don't put priority on everything, then it means nothing. One image per page, usually.
