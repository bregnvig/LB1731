The playground app has no images, so no lab. Know it for when you do. NgOptimizedImage: ngSrc instead of src. It matters when an image is the Largest Contentful Paint element. priority for the LCP image: fetchpriority high, eager, preload on SSR. width and height required, or fill with a positioned parent. Dev mode warns if the LCP image has no priority. This app has no images, so there is no exercise, but you will meet this on every real project. Replace src with ngSrc and import NgOptimizedImage. You get lazy loading by default, an automatic srcset when you configure an image loader, and dev mode warnings for the usual mistakes. It matters most for LCP, Largest Contentful Paint: the time until the biggest thing above the fold has rendered, often a hero image. Good is under 2.5 seconds. Put priority on that image: it gets fetch priority high, is not lazy, and with server side rendering it is preloaded. Angular warns in dev mode if the LCP image has no priority. Width and height are required so the browser reserves the space and the layout does not jump. If the size is not known, use fill, with a positioned parent, and object-fit in CSS. Do not put priority on everything, then it means nothing. One image per page, usually.
