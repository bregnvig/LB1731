Virtual scroll

  • Render only what is on screen, plus a few rows around it
  • Angular CDK: cdk-virtual-scroll-viewport, itemSize, *cdkVirtualFor
  • For thousands of rows. 133 rows: not worth it
<cdk-virtual-scroll-viewport itemSize="66" class="list">
  <loop-sidebar-list-item
    *cdkVirtualFor="let playground of playgrounds()"
    [playground]="playground"/>
</cdk-virtual-scroll-viewport>
Render only the rows in view, plus a few more. 133 rows -> about 15 in the DOM. Angular CDK: cdk-virtual-scroll-viewport, itemSize, *cdkVirtualFor. Not installed in this course: @angular/cdk is not a dependency. Name it, no lab. Use it for thousands of rows; for 133 it is overkill. Cut from the slide: "Not installed in this course: no lab". The strongest answer to a long list is not to render it. Virtual scrolling keeps only the rows that are visible, and a few around them, in the DOM, and swaps them as you scroll. In Angular it comes from the CDK: a viewport element with an item size, and cdkVirtualFor instead of @for. It needs fixed or estimated row heights. We do not have the CDK installed in these labs, so there is no exercise. I name it so you know it exists. Be honest about trade-offs: it changes how search in page and anchors work, and for 133 rows it is more machinery than it is worth. Think of it from a few thousand rows.
