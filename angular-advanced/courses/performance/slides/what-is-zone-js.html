What is Zone.js?

Patches events, timers, promises, XHR

Runs change detection after every task

Can't tell if state changed 🤔

Adds JavaScript to your bundle 🙄

Four clicks, one line each. Monkey patch: change runtime behaviour without touching the source. Patches setTimeout, setInterval, addEventListener, promises. Runs CD after each callback. Knows "a task ended", not "state changed". Costs bytes (polyfills, see exercise 2). Cut from the slide: "monkey patches"; "so Angular updates seamlessly 😁"; "so most cycles change nothing". Zone.js wraps the browser APIs that run your code later: addEventListener, setTimeout, setInterval, promises, XHR. Angular listens to the zone, and when a task finishes it runs change detection over the whole app. That is why Angular used to just work. You assign a field in a callback, and the screen updates. Nobody told Angular, the zone guessed. The price: it cannot tell whether anything changed, so every mouse move and every timer tick pays for a full cycle. And it is code in your bundle: we will see its size in the build output in exercise 2. Keep this in mind for the first lab: the map fires events constantly, and every one of them starts a cycle.
