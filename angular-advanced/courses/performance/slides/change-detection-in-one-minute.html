Change detection in one minute

  • Checks bindings against their old values
  • When, here: zone.js, after every event and timer. Since v21: zoneless
  • Which: Eager (was Default): all. OnPush: dirty ones

Demo after Matthieu Riegler

Before class: npm run start:no-hmr in demo/, open http://localhost:4201/performance/change-detection, press Reset counters. Demo: All Eager, click "click" on E: all seven nodes flash, checks 1 each. All OnPush, Reset, same click: only E, B, A flash (the screenshot, after two clicks). Credit: the demo is modelled on Matthieu Riegler's Angular change detection demo, https://jeanmeche.github.io/angular-change-detection/ Change detection keeps the screen in sync with your data. After something happens, Angular walks the tree from the root and compares every binding with its old value. So the cost is easy to state: how many components are checked, times how many bindings they have, once per cycle. Two levers: how often does a cycle run, and how many components does each one check? When: in today's app, zone.js decides. It patches events, timers and promises, and runs a cycle after every one. It knows a task finished, not that anything changed. New apps since Angular 21 are zoneless, and that's exercise 2. Which: Eager is the old Default, renamed: checked every time the walk passes. OnPush: only when something marked it dirty. Switch to the demo. All Eager, Reset counters, click "click" on E. Every node flashes yellow, seven checks for one click on a leaf. Now All OnPush, Reset, the same click: only E, B and A, like the screenshot. Ask the room: why A and B, when nobody clicked them? They're on the path from E to the root. The demo is built on Matthieu Riegler's change detection demo from the Angular team, so the credit goes to him.
