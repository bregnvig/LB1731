Change detection in one minute

  • Change detection keeps the DOM in sync with your state
  • It walks the component tree from the top and compares every template binding with its old value
  • The cost is components checked × bindings in them, every cycle

Two questions decide the cost

  • When does a cycle run?
  • Which components does it check?

Zone.js answers when (after every async task). OnPush and signals answer which.

CD = compare bindings, update the DOM. Cost = components checked x bindings, per cycle. When: zone.js (today's start), signals (zoneless). Which: Eager vs OnPush. Change detection is Angular's way of keeping the screen in sync with your data. After something happens, it walks the component tree from the root, and for every binding in every template it compares the new value with the old one and updates the DOM if it differs. That makes the cost easy to state: how many components are checked, times how many bindings they have, once per cycle. So there are two levers. How often does a cycle run, and how many components does each cycle check? Zone.js decides when cycles run in the app as we start. Today we replace that with signals, and we use OnPush to check fewer components. The full story is in the Components module.
