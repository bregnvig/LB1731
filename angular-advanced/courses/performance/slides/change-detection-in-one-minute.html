Change detection in one minute

Change detection compares every template binding with its old value.

  • When does a cycle run? Zone.js: after every event, timer and promise
  • Which components? Eager (the old Default): every component. OnPush: only what is marked dirty

Zone.js knows a task finished, not that state changed 🤔

Before class: npm run start:no-hmr in demo/, open http://localhost:4201/performance/change-detection, press Reset counters. Demo: /performance/change-detection. All Eager, click "click" on E: all seven nodes flash, checks 1 each. All OnPush, Reset, same click: only E, B, A flash. Cost = components checked x bindings, per cycle. When: zone.js. Which: Eager vs OnPush. Change detection keeps the screen in sync with your data. After something happens, Angular walks the tree from the root and compares every binding with its old value. So the cost is easy to state: how many components are checked, times how many bindings they have, once per cycle. Two levers: how often does a cycle run, and how many components does each one check? Switch to the demo. All Eager, Reset counters, click "click" on E. Every node flashes yellow, seven checks for one click on a leaf. Now All OnPush, Reset, the same click: only E, B and A. Ask the room: why A and B, when nobody clicked them? They're on the path from E to the root. Click for the last line. Zone.js decides when cycles run in today's app. It patches events, timers and promises, and runs a cycle after every one. It knows a task finished, not that anything changed.
