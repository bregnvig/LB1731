Measure, change, measure again

  1. Measure before: profile, record the number
  2. Change one thing
  3. Measure again, the same way

No fix without a before and after.

Guessing which part is slow is the most common performance mistake. Every exercise today follows these three steps.

The rule on every exercise slide. Same steps before and after, or the numbers mean nothing. Change one thing at a time, else you do not know which fix helped. This is the only rule of the day. Before you change code, you measure: a profiler recording, a build size, a heap snapshot. You write the number down. Then you change exactly one thing. Then you measure again in exactly the same way, and compare. Two reasons. First, developers are bad at guessing where time goes. Second, a fix that does nothing still feels like progress, and a fix that makes things worse can hide behind a lucky run. Every exercise slide has a Measure before and a Measure after, with what you should see.
