Heap snapshots

DevTools > Memory > Heap snapshot

  1. Trash icon: collect garbage
  2. Snapshot on the starting page
  3. Use the app, trash icon again
  4. Second snapshot, compare

Filter Detached, or a class name, and read Retainers

Chrome DevTools > Memory > Heap snapshot. Trash icon first (collect garbage), then Take snapshot. Compare two snapshots: Summary dropdown > Comparison, or just count instances. Class filter: type Detached. Click an object: the Retainers pane shows what keeps it alive. Shallow size = the object itself, retained size = what is freed with it. A heap snapshot is a photo of every object in memory. You take two and compare. Open DevTools, Memory tab, choose Heap snapshot. Click the trash can first, that forces a garbage collection, so what is left is really being held. Then Take snapshot. Do something in the app, home to detail and back a few times, collect garbage again, take a second snapshot. In the class filter type Detached. A detached DOM node is a node that is out of the page but still in memory, because something still points to it. Those are the leaks you can see. You can also filter by class name, like FooterComponent or LeafletComponent, and count instances. After four trips there should not be five footers. Click an object and look at the Retainers pane at the bottom: it shows the chain that keeps it alive. For the footer it ends in a timer. That is the pointer you need to cut. Shallow size is the object alone, retained size is everything that would be freed with it. Sort by retained size to find the big ones.
