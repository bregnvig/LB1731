WeakMap as a cache

  • WeakMap<object, V>: entries vanish with their key object
  • Fits: a result that depends on the object only
  • Not here: distance also depends on the location
const labels = new WeakMap<Playground, string>();

function label(p: Playground) {
  if (!labels.has(p)) {
    labels.set(p, p.name.toUpperCase());
  }
  return labels.get(p)!;
}

The key must capture everything the value depends on

Only if asked. Demo: /performance/leaks, step 5 (Map vs WeakMap). A WeakMap is a map whose keys are objects held weakly. If nobody else references the key object, it's garbage collected and its entry disappears. So the cache cannot keep stale objects alive, which a normal Map would. In this app the distance per row is already a computed. A WeakMap keyed by playground would hand back the old distance after the location changed. A cache is only correct when the key captures everything the value depends on.
