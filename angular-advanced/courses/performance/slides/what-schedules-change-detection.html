Zoneless: what schedules change detection?

A cycle is scheduled when

  • a signal read in a template changes
  • markForCheck() is called (the async pipe does it)
  • a template or host listener fires
  • ComponentRef.setInput is called
  • a dirty view is attached

It is not scheduled by

  • setTimeout or setInterval
  • a promise or XHR finishing
  • assigning a plain field

Also: NgZone.onStable and friends never emit, isStable is always true. SSR needs PendingTasks. Tests: fixture.whenStable().

Triggers: signal read in template, markForCheck/async pipe, bound listeners, setInput, attaching a dirty view. Not triggers: timers, promises, plain fields. That is why the footer will freeze. Breaks: onMicrotaskEmpty/onUnstable/onStable never emit; isStable always true. Source: angular.dev/guide/zoneless. Here is the list you need in your head. Without Zone.js, change detection is scheduled by a short list of things: a signal read in a template changes, markForCheck is called, which the async pipe does for you, a listener bound in a template fires, setInput is called on a component created in code, or a dirty view is attached. Look at what is not on the list: timers, finished promises, finished requests, and a plain field being assigned. Those used to work because the zone ran a cycle after them. Now they do nothing visible. The footer's setInterval writes a plain field, so the counter will freeze when we remove zone.js. Also be aware that NgZone events like onStable never emit, and isStable is always true, so code that waits on them needs another way. In tests, use fixture.whenStable. The rule of thumb: if the screen should change, change a signal.
