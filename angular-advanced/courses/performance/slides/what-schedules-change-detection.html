Zoneless: what schedules change detection?

  • A signal read in a template
  • A template or host listener
  • markForCheck(), the async pipe
  • Only zone.js: timers, promises, requests

If the screen should change, change a signal.

Clicks 1-3: the three that schedule a check, with or without zone.js. Click 4: the ones only zone.js schedules (setTimeout, setInterval, a promise or request finishing). Click: the rule. These three schedule a check, with or without zone.js: a signal read in a template, a listener in a template, markForCheck, which the async pipe calls for you. Click. Only zone.js: timers, promises, requests. These used to work only because the zone ran a cycle after every timer and every finished request. Zoneless, they schedule nothing. And assigning a plain field never scheduled anything, the next cycle just happened to pick it up. The footer's setInterval writes a plain field, so ask the room: what happens to the footer counter in exercise 2? It freezes. Switch to the demo. All OnPush, click start signal interval on B1. The click checks B1, B and A once: a listener marks the path to the root. Then watch: once a second the interval sets a signal, and only B1 flashes. A and B stay put. The signal marks B1 alone, and Angular walks down to it without checking the parents. Stop it. Now start primitive interval on B1: the same timer, but it adds one to a plain field. Nothing flashes, the number stays 0. Wait three seconds and stop it: the click checks B1, and it shows 3. The value was there all along, nobody told Angular. That's the footer in exercise 2. This demo runs zoneless. Click Zoneless ⇄, it reloads with zone.js, and do the same: the same nodes flash. Signals and listeners schedule a check either way, that's the first three items. And OnPush skips the plain field even with zone.js: nothing marked B1. Click. The rule of thumb: if the screen should change, change a signal.
