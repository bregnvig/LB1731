What does "slow" mean?

  • Startup: download, parse and first render. Big bundles, everything loaded eagerly
  • Interaction: clicks, typing and mouse moves feel laggy. Too much change detection, long tasks
  • Memory: fast at first, slower the longer you use it. Leaks, too many DOM nodes

Today's labs

  • Exercise 1 and 2: interaction
  • Exercise 3: startup
  • Exercise 4: memory and the DOM
Three kinds of slow, each with its own tool. Startup: ng build output, Network panel. Interaction: Profiler, Performance panel. Memory: heap snapshots. Labs 1+2 interaction, lab 3 startup, lab 4 memory. When a user says the app is slow, ask which slow. Startup is the wait before they can use it: JavaScript to download, parse and run. Interaction is lag after startup: you move the mouse or click and the screen answers late, usually because Angular does too much work per event. Memory is slow over time: it was fine when you opened it, and an hour later the tab is heavy because things were never cleaned up, or there are simply too many DOM nodes. Each kind has a different tool, and a fix for one does nothing for the others. That is why we measure first. The four labs go through all three.
