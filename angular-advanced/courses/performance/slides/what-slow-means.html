What does "slow" mean?

Slow to respond

Slow to start

Slower over time

Each has its own number. Measure it before you fix it.

Three clicks, three kinds of slow, then the rule. Respond: Profiler bars in 5 s of mouse moves (labs 1, 2). Start: Initial total from npm run build (lab 3). Over time: objects counted in a heap snapshot (lab 4). When a user says the app is slow, ask which slow. Click. Slow to respond: you move the mouse or click, and the screen answers late. Usually Angular does too much work per event. We count bars in the Angular DevTools Profiler, labs 1 and 2. Click. Slow to start: the wait before you can use the app. JavaScript to download, parse and run. We read Initial total in the build output, lab 3. Click. Slower over time: fine when you opened it, heavy an hour later, because things were never cleaned up. We count objects in a heap snapshot, lab 4. Click. Each kind has its own number, and a fix for one does nothing for the others. That's the only rule today: measure, change exactly one thing, measure again the same way. Developers are bad at guessing where time goes, and a fix that does nothing still feels like progress. Ask the room: which of the three did your last "the app is slow" ticket mean?
