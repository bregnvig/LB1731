Retainers on a detached node: Window -> _leaflet_events -> resize handler -> L.Map -> ... -> <main>. Click: the two culprits. Trap: DevTools console retainers. The "14,120 detached nodes" in older notes was every detached DOM node (elements, Text, Comment) summed from the raw snapshot by script. DevTools never shows that sum: the Summary has one "Detached <tag>" row per tag, plus blink:: internals. So students read one row. In snapshot two, type Detached in the class filter. You get a long list, one row per tag: Detached <div>, Detached <button>, and so on, and DevTools has no total for all of them. So read one row that means something: Detached <leaflet>. Ten. One map element per old Home, ten old Homes. If you want a bigger number, Detached <loop-sidebar-list-item> says 1,330: ten old lists of 133 rows. Then type FooterComponent: 11. One is the footer on screen, ten are leaked, two per round, like I said. Now click one of the detached nodes and read the Retainers pane. You'll see a chain like the one on the right: it starts at Window, goes through _leaflet_events, a resize handler, the Leaflet map, its container div, and from there up through the leaflet element and main into the whole old Home. Ask the room: who put a listener on window? Let them guess before you click. Click. Leaflet did. A map listens for window resize, and only map.remove() takes the listener off. Nobody calls it, so the map keeps its container, and a detached node keeps its parents, so the whole old Home stays. The footer is the other half: the setInterval callback still runs every second and holds the footer. The trap: if you click around in the Elements panel or log a node to the console, DevTools itself holds on to it, and it shows up with DevTools console as its retainer. That's not your app. Ignore those.
