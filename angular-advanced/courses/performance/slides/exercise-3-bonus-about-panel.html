Exercise 3 - Bonus: Om appen

A panel behind a click? @defer (on interaction) or (when open()) comes first. import() + NgComponentOutlet is for a type chosen at runtime, e.g. by a dialog service. Practise it here; it's in the solution.

New file src/app/about/about.component.ts: a standalone AboutComponent with <h4>Om appen</h4> and a sentence.

In src/app/footer/footer.component.ts: a signal holding the component type, await import(...) on click, and *ngComponentOutlet to show it (add NgComponentOutlet to imports).

npm run build: a new lazy about-component chunk of 481 bytes. With npm start -- --no-hmr it loads on the first click only.

about = signal<Type<unknown> | null>(null);

async toggleAbout() {
  if (this.about()) {
    this.about.set(null);
  } else {
    const { AboutComponent } = await import('../about/about.component');
    this.about.set(AboutComponent);
  }
}
Already in solution 3 (labs/performance/exercise-4 has it). Lazy dynamic component: await import + NgComponentOutlet. Premise: for a fixed panel behind a button, @defer (on interaction) or (when open()) is simpler. import() + NgComponentOutlet is for when code decides the type at runtime: a dialog service, a CMS-driven widget, a plugin list. Build: about-component 481 bytes in the lazy table. --no-hmr Network: about.component-….js on the first click, nothing on the next ones. Template: <ng-container *ngComponentOutlet="about()"/>. Alternative: ViewContainerRef.createComponent. For those who are done. First, be honest about when you'd use this. If the panel is always the same component behind the same button, @defer on interaction, or when with a signal that the button sets, does it in the template and you're done. This bonus is for the other case: the component type is decided in code. A dialog service that gets a component to open, a dashboard that builds widgets from a config. Our Om appen panel is the smallest place to practise that by hand. Step one: await import() gives you the file, and from it the component class. The bundler puts that file in its own chunk, so nothing is downloaded until that line runs. Step two: render it. NgComponentOutlet takes a component type and renders it, and with null it renders nothing. The signal holds the type, so it works zoneless too. The other way is createComponent on a ViewContainerRef; NgComponentOutlet is shorter. Build and you get a tiny lazy chunk, about-component, 481 bytes. In the browser with no HMR, open Network, click Om appen: one request. Close it and open it again: no new request. It's already in the solution, so if you didn't get to it, open the footer there. Ask the room: where in your app does code, not a template, decide which component to show?
