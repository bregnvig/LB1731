Exercise 3 - Bonus: Om appen

import() + NgComponentOutlet: for a type chosen at runtime, like a dialog service. A fixed panel? @defer (on interaction) or (when open()) is simpler.

New file src/app/about/about.component.ts: a standalone AboutComponent with <h4>Om appen</h4> and a sentence.

In src/app/footer/footer.component.ts: a signal holds the type, await import(...) on click, *ngComponentOutlet shows it (add NgComponentOutlet to imports).

about = signal<Type<unknown> | null>(null);

async toggleAbout() {
  if (this.about()) {
    this.about.set(null);
  } else {
    const { AboutComponent } = await import('../about/about.component');
    this.about.set(AboutComponent);
  }
}
Lazy dynamic component: await import + NgComponentOutlet. Premise: for a fixed panel behind a button, @defer (on interaction) or (when open()) is simpler. import() + NgComponentOutlet is for when code decides the type at runtime: a dialog service, a CMS-driven widget, a plugin list. Template: <ng-container *ngComponentOutlet="about()"/>. Alternative: ViewContainerRef.createComponent. For those who are done. First, be honest about when you'd use this. If the panel is always the same component behind the same button, @defer on interaction, or when with a signal that the button sets, does it in the template and you're done. This bonus is for the other case: the component type is decided in code. A dialog service that gets a component to open, a dashboard that builds widgets from a config. Our Om appen panel is the smallest place to practise that by hand. Step one: a small AboutComponent in its own file. Step two: await import() gives you the file, and from it the component class. The bundler puts that file in its own chunk, so nothing is downloaded until that line runs. Step three: render it. NgComponentOutlet takes a component type and renders it, and with null it renders nothing. The signal holds the type, so it works zoneless too. The other way is createComponent on a ViewContainerRef; NgComponentOutlet is shorter.
