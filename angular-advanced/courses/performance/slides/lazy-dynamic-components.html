Lazy dynamic components

The template cannot say it up front: a click decides

await import(...) gives the class, in its own chunk

NgComponentOutlet renders a Type (or null: nothing)

Or createComponent on a ViewContainerRef

about = signal<Type<unknown> | null>(null);

async toggleAbout() {
  if (this.about()) {
    this.about.set(null);
  } else {
    const { AboutComponent } = await import('../about/about.component');
    this.about.set(AboutComponent);
  }
}

<ng-container *ngComponentOutlet="about()"/>
@defer needs the component in the template. When code decides at runtime: import() + render it. await import(...) gives the class; NgComponentOutlet renders a Type. Or ViewContainerRef.createComponent(Type). Bonus in the exercise: the "Om appen" panel. Sometimes there is no place in a template for @defer: the user clicks a button, and only then do you know you need the component. Then you do it by hand. Step one: await import() gives you the file, and from it the component class. The bundler puts that file in its own chunk, so nothing is downloaded until this line runs. Step two: render the class. NgComponentOutlet takes a component type and renders it; with null it renders nothing. The other way is to call createComponent on a ViewContainerRef. NgComponentOutlet is the shorter one, so that is what the bonus uses. The signal holds the type. When it changes from null to the class, the outlet renders it, and since it is a signal it works zoneless too.
