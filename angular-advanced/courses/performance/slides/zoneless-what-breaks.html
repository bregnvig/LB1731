Four things that break when zone.js goes. Only the first one is in our app: the footer. Inputs: under OnPush a mutated object has the same reference, so nothing marks the child. fakeAsync needs zone.js/testing. NgZone.onStable and onMicrotaskEmpty never emit zoneless. Before you take zone.js out in exercise 2, here's what to look for in your own code. First row, the one you'll hit today: a plain field written in setTimeout, setInterval, a promise or a subscribe. With zone.js, the cycle after the task picked it up. Zoneless, nothing schedules a cycle, so the screen stays where it was. Make it a signal. That's exactly the footer counter in a minute. Second: an input object you mutate in place, like pushing to an array a child gets as an input. Same reference, so OnPush sees no change and the child stays stale. Pass a new array or a new object, or make it a signal. Third, tests. fakeAsync and tick are built on zone.js. Keep zone.js/testing in the test polyfills for those specs, or move them to real timers or your test runner's fake timers. Fourth: code that waits for the zone to settle, NgZone.onStable or onMicrotaskEmpty, often in third-party wrappers or old directives. Zoneless, those never emit. If what you want is "after Angular has rendered", that's afterNextRender. Ask the room: grep your app for fakeAsync and onStable. How many hits?
