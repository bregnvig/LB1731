@defer and its triggers

Components, directives and pipes used only in the block move to a lazy chunk

Default trigger: on idle

Combine with ;, any one fires

prefetch on ... downloads early, renders later

when is one-shot

@defer (on idle) { ... }
@defer (on viewport) { ... }
@defer (on interaction(btn)) { ... }
@defer (on hover(btn)) { ... }
@defer (on timer(5s)) { ... }
@defer (when loggedIn()) { ... }

@defer (on interaction(btn); prefetch on idle) { ... }
@defer moves the template block's components, directives and pipes into a lazy chunk. Default trigger is on idle. OR them with ; on viewport / interaction / hover watch the placeholder (or a template reference). prefetch = download early, show later. The exercise uses idle for the map and viewport for the footer. @defer is lazy loading for part of a template. Everything inside the block that is only used there: components, directives, pipes, goes into its own chunk and is fetched when the trigger fires. Triggers: on idle waits for the browser to be idle, on viewport waits for the placeholder to scroll into view, on interaction and on hover react to the user, on timer waits a fixed time, on immediate starts right away but still outside main, and when takes any condition. when is one-shot: once it was true, the block stays. Several triggers are combined with a semicolon and any of them fires. Prefetch is a separate trigger: it downloads the chunk, but does not show the block. So you can prefetch on idle and show on interaction, and the click feels instant. In the exercise you wrap the map in on idle and the footer in on viewport. Do not guess which is the biggest win: measure.
