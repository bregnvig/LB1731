@defer and its triggers

  • Used only in the block: moves to a lazy chunk
  • on idle is the default. on viewport watches the @placeholder
  • A viewChild of it outside the block: no chunk
@defer (on idle) {
  <leaflet [center]="center()"
    [markers]="markers()"/>
} @placeholder {
  <div class="vh-100 vw-100"></div>
}
@defer (on viewport) { … }
@defer (on hover(btn); prefetch on idle) { … }
Demo: /performance/defer (demo on npm run start:no-hmr). Network, filter JS, reload: idle + prefetch chunks at once, timer at 3 s; hover "Hover me": hover-loaded chunk. Click "Downloaded already. Click me": renders, no new request. Then: throttle to Slow 4G, reload, click "Click me": "Loading ..." for about a second. Set throttling back to No throttling. viewChild(LeafletComponent) in Home on top of the defer: no leaflet chunk (measured on a copy of the exercise 3 start). @defer is lazy loading for part of a template. Everything inside the block that's only used there, components, directives, pipes, goes into its own chunk and is fetched when the trigger fires. Let me show you. Network tab, filter JS, reload. The idle card and the prefetch chunk come in right away, the timer card three seconds later. Ask the room: what happens when I hover "Hover me"? A new request. Now "Downloaded already. Click me": it renders, no new request. That's prefetch: download early, show later. The placeholder: what the user sees until the trigger fires. Give it the size of the content, or the page jumps. In the exercise the map placeholder is an empty full-size div. On viewport, hover and interaction without a reference watch the placeholder, so it needs exactly one root element. Throttle to Slow 4G, reload, click "Click me": the loading block shows for about a second. Then set throttling back to No throttling, or the rest of the demo crawls. Click through the trap: if anything outside the block uses the component, even a viewChild of it, it stays eager and there's no chunk. The build won't warn you; look for the chunk in the lazy table.
