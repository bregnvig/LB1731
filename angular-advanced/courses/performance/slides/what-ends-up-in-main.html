What ends up in main?

  • Everything imported at start, and what that imports
  • Registered means used: a whole icon pack can't be tree-shaken
  • A side-effect import stays, used or not
// only faSpinner ships
import { faSpinner }
  from '@fortawesome/free-solid-svg-icons';

// every icon in the pack ships
import { fas }
  from '@fortawesome/free-solid-svg-icons';
library.addIconPacks(fas);

Find the weight before you @defer anything.

Tree-shaking keeps what's used. A registered pack is "used": every icon in it ships. Side-effect imports (import 'x') always stay. Exercise 3 opens with the esbuild analyzer on our main. The bundler only keeps code that something uses. That's tree-shaking. Import one icon by name and use it: one icon ships. The catch is what counts as "used". Hand a whole pack to a function, like addIconPacks, and every icon in that pack is used as far as the bundler can tell. It has no idea which ones your templates will ask for at runtime. Same with a side-effect import, import 'some-lib' with no names: the bundler has to keep it, because running it is the point. Click. So before you start splitting things with @defer, find out what's actually heavy. That's the first step of exercise 3. Ask the room: who knows what's in their own main bundle?
