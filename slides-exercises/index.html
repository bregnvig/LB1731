npm install -g typescript

  • Goto the 01-simple-typescript folder
  • Start the compiler tsc -w 

Create an interface

  • Open the file simple-typescript.ts in your editor
  • Create an interface called IVATCalculator
  • Define a single method calculate the takes a parameter of type number and return a number
  • Look at the compiled js file placed in ./js folder. Notice it is empty. Why is that?

Create the class

  • Stay in the same .ts file
  • Create a class that implements the interface
  • The calculate method should multiply the parameter with 1.25 and return the result

The coordinate is already part of the solution and just needs to be imported into the playground.ts file using:

import { Coordinate } from './coordinate';

Exercise 5

Create a footer component

In this exercise you can choose to, either stay in the previous directory and continue there, or you can navigate to the 04-create-footer-component directory and continue there. (You need to run npm install, if you choose to change directory)

Make a presentation component of the sidebar

Right now, even though it is a bit simple, the sidebar knows how to get a reference to the playgrounds to display. This makes it a smart component. Again, currently this is kind of simple.

Instead let’s make the AppComponent the smart component. Copy the playgrounds property from the sidebar component to the app component and rename it to appPlaygrounds.

Next delete the assignment of the playgrounds property in the sidebar component and prefix the property with input. Make it required

Remember to import it from @angular/core module. If you save now, no playgrounds are shown😲

Next step is to assign the sidebars playgrounds property using the property data binding syntax, used in the parent → child scenario.

Now the sidebar has no knowledge of how the playgrounds were fetched👌

Mark playground as selected

Before we create an output from the sidebar component, mark the playground that is clicked on, using the CSS class active.

To do this we will add a click event listener to the <li> element. When clicked, it should invoke a method called selectPlayground. This method sets the state of a signal called selectedPlayground with the playground value.

Using property data binding, set the <li> element CSS class to active, when the selected playground is equal the playground in the @for loop.

Hint: [class.active] = "???"

Create output

Let’s create some output using the output function!

Start by adding a property called selected to the sidebar.

Assign it to an instance of output function. Remember to use generics! Our event emitter emits a Playground.

   
When all this is done, emit the selected playground in the selectPlayground method we previously created. 

Listen to the event

Going back to the app component, we need to listen for this event.

We can only listen for events on the child elements that emit them, so two siblings cannot communicate directly using event emitters.

So create a method called playgroundSelected in the app component. When called it should set a property called playground to the given value.

Lastly update the app template to listen to the event from the sidebar component and call the method.

Before proceeding to the next exercise try to log out the selected playground using console.log()🤓
 

Create the footer component

Using the Angular CLI, create a new component called footer. Include this new component inside the app component template.

When you save the files, you can see that the footer component has been added to the view. You will need to scroll down

Add playground input

Right now, the footer component does not have access to any playground. So, let’s add a playground property of generic type Playground to the footer component class.

Using the parent → child style, we assign it to the value of the input function to our new playground property. 

Update the footer template

Let’s change the footer component template from “footer works” to something more useful.

The footer must show info about a playground. It should show the playground's name, address description and description.

The root element of the template must be a <footer> HTML5 element. Within the footer element place a <h3> element and two <p> elements. Place the playground name in the <h3>, the address description in the first <p> and the general description in the second <p>. All using interpolation.

When we save our files now, the application still loads, but we should see a lot of errors in the developer tool.

Why is that? Well, unless we used the Elvis notation, accessing the properties name, addressDescription and description will results in an error like this:
Cannot read property '<property-name>' of undefined

But even if we fixed this by adding the ? to all our interpolations,  and thereby fixing these errors, we would still have the footer element in the view, even when no playground is selected. That’s not very pretty!

So instead, let’s make the entire footer element disappear when no playground is selected. Remember a certain build-in conditional statement to achieve that?

Update the template, save the files, and verify the errors have disappeared.

Bind playground to footer

The final thing we need to do is to bind the playground property from the app component to the input property of footer component.

Update the app template with this property data binding!

Create a playground service

In this exercise you can choose to, either stay in the previous directory and continue there, or you can navigate to the 06-create-playground-service directory and continue there. (You need to run npm install, if you choose to change directory)

Create the playground service

Let’s start out by creating a simple service with a single method. Let’s call the service PlaygroundService and the method getPlaygrounds. The method must return an array of playgrounds.

Normally a method calling a backend service would return a promise or an observable, but for now, since we have not talked about any of these, the getPlaygrounds method should just return the mock array from earlier.

Create the service using the Angular CLI and place the service in the shared folder.

Inject the service into the app component

Let’s finish off by injecting the service into the app component.

We do that by adding one parameter to the app components constructor. Like this:

service: PlaygroundService

Remove any and all reference to the MOCK_PLAYGROUNDS array in the app component.

Isn't refactoring wonderful🥳

 

Lastly assign the result of the getPlaygrounds method to the instance variable appPlaygrounds. Consider doing this in the constructor instead of the ngOnInit. Why am I saying this?

When you save the files, you should see no difference between using the MOCK_PLAYGROUNDS and using the playground service. But this will change very soon!

Updating the map component

It seems like the sidebar is working but notice that when we click a playground the URL does not change.

So, update the map component to navigate to the correct URL, when the sidebar emits a playground.

Start by injecting the Router service. Next use its navigate method

Try to click on a few playgrounds. And then notice how the back and forward buttons work as expected! (At least in the address bar)

But we are not done. Try to select a playground, now reload the page. Notice that the selected playground is no longer selected.

This is because the selectedPlayground in the sidebar component has not been initialized when we reloaded. Remember that the sidebar should not read from the URL, as it is a presentation component and should have no context.

Make the selectedPlayground property assignable from the parent. (Remember component communication?)

It still don't work when you reload, but soon it will

Assign the selected playground to the sidebar

Back in the map component we need to find the selected playground based on the URL.

So, let’s start by adding a find method to the playground service. This method should take a single parameter id: string, and return an Observable<Playground>. This should be doable using the map operator on the existing playgrounds$. This should be a one-liner!

Now we just need the id from the URL!

Inject ActivatedRoute. Using the id from the URL and the new find method in the playground service, we should convert playground property to a Signal using toSignal. We are going to need switchMap to do this.

If you reload the page the footer should have started working again.

This still didn’t mark the playground as selected in the sidebar. But all there is left to do, is to assign the selectedPlayground property in the sidebar component using the property data binding syntax.

center and zoom

Our application is almost complete! 

But when we select a playground we need to center the map on the selected playground.

And if no playground is selected, center on Denmark.

Change the center to be a computed signal. Inside the computed use the playground signal either setting center using the playgrounds position or fallback to the center of Denmark. Set the zoom level to 14.

Add markers

We know leaflet uses a marker array as input.

We need two markers, one for the playground and one for our current position.

Luckily we already know about the computed signal.

Use the location service and combine it with the playground signal.

Make sure to return an array of two markes.
