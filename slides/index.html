What is angular?

What?

Angular is a platform that helps you create advanced web applications in HTML using TypeScript

 

Why?

Big web applications can easily get messy. A framework helps you structure your code, separate your concerns and remove trivial code

Why Angular?

Why should you choose Angular?

  • Angular contains a lot of features – for HTML generation, data binding, dependency injection etc.
  • Backed by Google / well documented
  • Active community
  • Performance
  • Multiple platforms (Web, Electron and NativeScript)

Why should you not choose Angular?

  • If you dislike JavaScript/TypeScript
  • If you would rather do React or vue.js application

What about standalone?

  • Are the default since v17
  • Simplify the development of components, directives and pipes
  • State your own dependencies
  • Modules no longer needed
  • The CLI can help you migrate to standalone
  • Applications can optionally and incrementally adopt
  • Modules are not deprecated, but it sounds like they will be...

what is a signal?

Create and manage dynamic data

  • It's a lightweight wrapper around a value
  • It can be used by calling it. E.g. value()
  • There are quite a few signals, and growing, in Angular
  • Notifies interested consumers when that value changes, enabling fine-grained, automatic change detection. I.e better performance

Signal forms🚦

  • New in v22 - and no longer experimental

  • The model is just a signal - no FormGroup, no FormBuilder

  • The form is derived from the shape of your model

  • Validation is declared as rules against the model - checked at compile time

  • Import from @angular/forms/signals

interface PersonModel {
  firstName: string;
  lastName: string;
  favoriteColor: string;
  height: number;
}

export class SignalFormComponent {

    firstName: 'Flemming',
    lastName: 'Bregnvig',
    favoriteColor: 'Blue',
    height: 182,
  });

  protected fg = form(this.#model, (person) => {
    required(person.firstName);
    required(person.lastName);
    min(person.height, 100);
    max(person.height, 220);
  });

}

[formField] binds one field - the field tree knows its own type

Field state is signals all the way down

fg().value()      // the whole model
fg.firstName().value()    // one field's value

fg().valid()      // is the form valid?
fg().invalid()
fg().touched()
fg().dirty()
fg().errors()     // typed validation errors

fg.height().errors()      // errors for a single field

Everything is a Signal, so the template just reads it - no valueChanges subscription

  • Template driven - state lives in the template

  • Signal forms - state is your model, the form is derived from it

  • Signal forms fit a zoneless, signal based application🚀

  • Reactive forms are not going anywhere - but new code can start here

Link parameter array

  • Both the Router service and the [routerlink] directive uses the link parameter array
  • Primitives in the array will be added as part of the path
  • Object in the array will be added as matrix parameters. So what is a matrix parameter you might ask🤔

Reading parameters

Read parameters using snapshot

export class OrderComponent {

  #service = inject(OrderService);
  #route = inject(ActivatedRoute);

  constructor() {
    this.#service.getById(this.#route.snapshot.params['id']).subscribe(...);
  }
}

Read parameters continuously

export class OrderComponent {

  #service = inject(OrderService);
  #route = inject(ActivatedRoute);

  constructor() {
    this.#route.params.pipe(
      switchMap(params => this.#service.getById(params['id']))
    ).subscribe(...);
  }
}
