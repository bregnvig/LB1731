Instructor demo - httpResource in a test

Same fake backend, same URL. Not an exercise: watch, then ask questions.

• httpResource starts the request eagerly, not on subscribe. It needs an injector in a test.

• TestBed.tick() runs the effect that sends the request. Then expectOne and flush.

• Wait for stability before reading. Check hasValue() before value(): reading it in the error state throws.

// Arrange
TestBed.configureTestingModule({ providers: [provideHttpClientTesting()] });
const httpTesting = TestBed.inject(HttpTestingController);
const playgrounds = httpResource<Playground[]>(() => 'assets/copenhagen.json', { injector: TestBed.inject(Injector) });
// Act
TestBed.tick();
httpTesting.expectOne('assets/copenhagen.json').flush([havnegade]);
await TestBed.inject(ApplicationRef).whenStable();
// Assert
expect(playgrounds.hasValue()).toBe(true);
expect(playgrounds.value()).toEqual([havnegade]);
Optional demo, ~5 min. httpResource is not in the app; this is test-local. Differences from HttpClient: eager, needs injector, TestBed.tick(), whenStable, hasValue before value. Imports: httpResource from @angular/common/http; ApplicationRef, Injector from @angular/core. Signals world, same idea. httpResource wraps HttpClient, so the same testing controller works. Two differences. First, it is eager: the request is sent without anyone subscribing, once the effect runs. In a test we give it an injector and call TestBed.tick() to run that effect. Then expectOne and flush as before. Second, the value arrives through signals, so wait until the app is stable. Then check hasValue before value, because reading value while the resource is in the error state throws. Everything else you just learned carries over.
