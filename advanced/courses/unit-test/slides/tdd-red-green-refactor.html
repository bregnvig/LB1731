TDD: red, green, refactor

1. Red

Write one test for behaviour that does not exist yet. Run it. It fails.

2. Green

Write the least code that makes it pass. A hardcoded value is allowed.

3. Refactor

Clean up with the bar green. The tests tell you if you broke something.

Then the next test. Each new test forces the code to be a little less of a trick.

Exercise 1: christianshavn allows a hardcode, århus breaks it.

Red: one failing test. Green: least code. Refactor: clean up, still green. Repeat. A hardcode is a legal green. The loop has three steps. Write one test for something the code cannot do yet and watch it fail. Write the least code that makes it pass, even a hardcoded return value. Then clean up while the bar is green. The hardcode is not cheating. It is what makes the next test necessary: when the second test breaks it, you have a reason to write the real code. That is what you do in the first exercise.
