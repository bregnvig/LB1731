Testing code that calls HttpClient

HttpClient is the third party. No real network in a unit test.

• provideHttpClientTesting() swaps in a fake backend. It replaces HttpClientTestingModule, and HttpTestingController replaces a createSpyObj HttpClient.

• HttpTestingController: expectOne(url) finds the pending GET, flush(body) answers it

• The GET only starts on subscribe: firstValueFrom(...) first, then expectOne

• verify() in afterEach fails on unanswered or unexpected requests

describe('PlaygroundService', () => {
  let service: PlaygroundService;
  let httpTesting: HttpTestingController;

  beforeEach(() => {
    TestBed.configureTestingModule({
      providers: [provideHttpClientTesting()],
    });
    service = TestBed.inject(PlaygroundService);
    httpTesting = TestBed.inject(HttpTestingController);
  });

  afterEach(() => {
    httpTesting.verify();
  });

  // it(...) cases below
});
  it('should return only the playgrounds whose name contains the query', async () => {
    // Arrange
    const result = firstValueFrom(service.search('christianshavn'));
    // Act
    httpTesting.expectOne('assets/copenhagen.json').flush([havnegade, panterensBastion]);
    // Assert
    expect(await result).toEqual([panterensBastion]);
  });
Third party = HttpClient. Fake it with provideHttpClientTesting (replaces HttpClientTestingModule; the controller replaces a createSpyObj HttpClient). Order: subscribe (firstValueFrom), then expectOne, then flush, then await. Cold observable: no subscribe, no request, expectOne fails. verify() in afterEach: nothing left over. The service's unit of work ends where HttpClient starts: HttpClient is the third party, as in the Osherove model this morning. We never hit the network. provideHttpClientTesting replaces the backend. If you know HttpClientTestingModule or a createSpyObj HttpClient, both are gone: the provider and HttpTestingController do that job now. HttpTestingController is your remote: expectOne with the URL finds the one pending request, flush answers it with the body you choose. The order on the bottom matters. HttpClient is cold: the GET starts when somebody subscribes. firstValueFrom subscribes. So start firstValueFrom first, then expectOne, then flush, and only then await the result. Swap the first two and expectOne fails because nothing was requested yet. verify in afterEach catches requests nobody answered or nobody expected. Your turn.
