Why unit tests

Someone "tidies" the playground filter:

return playgrounds.filter(playground => playground.name.includes(query));

The app builds. The list still shows. Nothing is red.

Until a user types christianshavn and gets nothing.

By hand: npm start, npm run server, log in, wait for the list, type a query, look.

With a test: save the file. One second later the bar is red and names the case that broke.

The test is the check you would have run by hand, written down so it runs on every save.

Tidy-up breaks case-insensitive search; nothing else notices. By hand: log in, wait, type, look. Test: save, red in a second. No pep talk: the test is a check you already do, written down. Take one concrete change. Someone tidies filterPlaygrounds and drops the toLowerCase. The code still compiles, the app still starts, the list still shows every playground. Nothing looks wrong until a user types christianshavn in lower case and gets an empty list, because the name says Christianshavns with a capital C. To catch that by hand you start the server and the app, log in, wait for the list, and type the query. With a unit test you save the file and one second later Vitest tells you which case broke. That is all a unit test is: a check you would otherwise do by hand, written down once so it runs on every save.
