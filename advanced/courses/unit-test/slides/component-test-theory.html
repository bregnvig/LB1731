Testing a component: what a person sees

Assert the DOM, not the fields.

• Inputs: fixture.componentRef.setInput(name, value), not an assignment

• await fixture.whenStable() renders. The tests are zoneless (src/test-providers.ts)

• Read it back with querySelector and textContent

• Typing: set value, dispatch an input event

• Zoneless and OnPush only re-render on a notification: setInput, a signal the template reads, an event. A plain field write is ignored.

// Arrange
fixture = TestBed.createComponent(PlaygroundSearchComponent);
element = fixture.nativeElement;
fixture.componentRef.setInput('playgrounds', [havnegade, panterensBastion]);
await fixture.whenStable();

// Act
const field = element.querySelector('input')!;
field.value = query;
field.dispatchEvent(new Event('input'));
await fixture.whenStable();

// Assert
expect(element.querySelector('ul')!.textContent).toContain('Ingen legepladser');
A component test asserts what a person sees: text in the DOM. setInput for inputs. await fixture.whenStable() to render. querySelector + textContent. Typing = set value + dispatch 'input'. Plain field write: no notification, no re-render. No detectChanges needed. A component has a template, so its output is what a user sees. Assert that: text in the DOM. Not the component's private fields. Inputs are signals, you cannot assign them. Use fixture.componentRef.setInput with the input name. Then await fixture.whenStable(): the tests run zoneless, so this renders the template. See test-providers.ts if you want to know why. To read what is shown, querySelector and textContent. To type, set the field's value and dispatch an input event, then wait for stability again. Why not just write to a field on the component? Zoneless and OnPush change detection only run after a notification: setInput, a signal the template reads, or an event handler. A plain field write gives none, so the DOM stays old. That is also how the real app behaves.
