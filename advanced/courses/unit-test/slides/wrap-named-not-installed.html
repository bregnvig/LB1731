• Vitest browser mode: run the same specs in a real browser, with real layout and events.

• MSW: one fake API for the app and for tests, at the network level. Does not stack with provideHttpClientTesting.

• Stryker: mutation testing. It deletes and changes your code and checks that tests fail: the deletion question, automated.

• vitest-axe: accessibility checks (axe-core) on the rendered component.

• coverage: shows which lines ran, not whether anything was asserted. A weak oracle has 100% coverage.

One line each. Nothing installed today. Browser mode: real browser. MSW: fake the network, not HttpClient. Stryker: automated "delete the code". vitest-axe: a11y. Coverage: ran, not checked. We do not install any of these today. Know the names for when you need them. Browser mode runs your specs in a real browser instead of a simulated DOM. MSW fakes the network itself, so one set of fake responses serves the app and the tests. Stryker is the oracle exercise, automated: it breaks your code on purpose and tells you which breakages no test noticed. vitest-axe adds accessibility checks to component tests. Coverage tells you which lines ran, not whether any test looked at the result. Use them as the next steps once the basics here feel natural.
