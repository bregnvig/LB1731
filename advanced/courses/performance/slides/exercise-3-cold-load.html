Production builds, step-3 vs step-4, npx serve with gzip, fresh context, cache off, CPU 4x, DevTools Slow 4G preset. Medians of 3: FCP 4.4 s -> 2.3 s, LCP 9.4 s -> 7.4 s. JS transferred 477 kB -> 160 kB. LCP element is always a map tile. Step-4 with vs without the map @defer: LCP medians 80 ms apart (Slow 4G), 84 ms (Fast 4G), but the runs overlap: say "not worse", never "80 ms earlier". What does that mean for a user? We served both builds for real and loaded them with Chrome's Slow 4G preset and the CPU slowed down four times. Click. First contentful paint, when something shows: 4.4 seconds before, 2.3 after. Click. Largest contentful paint: 9.4 down to 7.4 seconds. It's that late because the backend takes three seconds on purpose, and the largest element is a map tile. Click. And the worry from the map slide: deferring the map trades a smaller first download for a map that paints later. So we measured that too: with the map deferred, LCP was not later, it was 80 milliseconds earlier, because the list and the rest of the page compete less for the network. Measure it in your app, it can go either way.
