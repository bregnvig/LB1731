Why not do it the IMPERATIVE way?

  • Interaction with UI is by nature asynchronous and unpredictable
  • Only one thread, so we need to be asynchronous, or we'll block the thread
  • Lot's of state
  • Hard to read 😁
Asynchronous UI: UI events, like button clicks, can happen anytime, making it tricky to manage with imperative code. Single Thread: If we process tasks sequentially, like waiting for a network request, the UI can freeze—users hate that! State Complexity: Imagine tracking every variable change manually—lots of if statements and callbacks everywhere. Readability: Nested callbacks or complex state management makes code look like spaghetti—hard to debug!
